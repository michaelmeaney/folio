# Practical benchmark quality and optional connectors

## Context

The real Quick conversion looked useful to the user, while exact internal-arrow checks treated an illustrative Excalidraw canvas as a technical topology. Generation consumed most of the shared trial deadline. The user approved separate quality dimensions, impact-based review, practical editing and deferring universal attached connectors.

## Decision

Extend [ADR 002](adr-002-go-benchmark-orchestration.md) with opt-in independent generation/review allowances and a versioned `practical-v1` evaluator policy. Preserve old frozen suites, results and strict legacy judgment. This policy measures a practical conversion milestone; it does not replace [ADR 001](adr-001-composition-preserving-transformations.md) or full Folio acceptance.

Label reference regions by purpose and relationship scope. Inspect exact topology only where it carries meaning. Evidence-backed minor illustrative differences are observations; changed technical meaning, missing required content, unreadability and flattened core content block.

Report visual fidelity, content/meaning, editability and accessibility independently. The first three gate practical quality; accessibility and runtime/application verification remain visible separately. A quality pass must not imply accessibility conformance, verified host editing or controlled-runtime parity. Runtime evidence remains necessary for comparable runs.

Practical editing requires native editable text and independently movable major elements. Disclose crops and unattached lines. Attached connectors are optional capabilities unless explicitly required by a case. Retain endpoint/move checks for claims of attachment.

## Consequences

Standards remain observable without making incidental illustration topology or unsupported host software a universal blocker. Reports retain process outcomes separately from quality findings. Historical evidence is never silently regraded; new suite/evaluator fingerprints make old/new datasets incomparable. See [plan 004](../plans/plan-004-practical-benchmark-quality.md).
